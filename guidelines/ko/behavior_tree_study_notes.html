1. 이 논문은 왜 Behavior Tree를 사용하는가?

논문에서 BT는 의사결정 모델(decision-making model)을 구현하기 위해 사용된다. 저자들이 직접 제시한 핵심 이유는 FSM의 관리 한계, BT의 확장성, 그리고 WVR 공중전에서 필요한 반복적·즉각적 상황판단이다.

원문 근거 ①

FSM은 복잡해지면 관리가 어려움

논문은 FSM이 구현하기 쉬운 방식이지만, 상태 수가 증가하거나 상태 전이가 복잡해질수록 관리하기 어려워진다고 설명한다.

Source: Sec. IV-A “System Structure”, journal p.32
원문 근거 ②

BT는 확장성이 높음

BT는 의사결정을 트리 형태로 정의하며, 더 정교하고 복잡한 의사결정이 필요할 때 nonleaf node를 추가할 수 있어 highly scalable하다고 논문에서 명시한다.

Source: Abstract; Sec. IV-A, journal pp.28, 32
원문 근거 ③

매 순간 다시 판단하기에 적합

WVR 공중전에서는 상황이 매 순간 크게 변하고 즉각적인 판단이 필요하다. 논문은 tick event가 발생할 때마다 BT가 반복 평가되므로 순간적인 상황판단에 이점이 있다고 설명한다.

Source: Sec. IV-B “Decision Model Using Behavior Tree”, journal p.32
논문에서의 역할을 한 문장으로:
BT는 BEM에서 추출해 만든 공중전 flow diagram을 실제 시뮬레이션에서 실행 가능한 decision-making AI model로 구현하는 수단이다.
학습용 해석
이 논문에서 BT의 장점은 “BT 자체가 전술을 새로 학습한다”는 데 있지 않다. 오히려 이미 BEM과 flow diagram에 명시된 조종사의 판단 논리를 관리하기 쉽고, 반복 평가 가능한 프로그램 구조로 옮긴다는 데 있다.

2. Behavior Tree를 보기 전에 먼저 알아야 할 기본 용어

Sequence나 Selector부터 외우기 전에, 먼저 Tree 구조에서 노드들이 어떤 관계를 가지는지를 잡아두는 편이 훨씬 쉽다. 아래는 기초 용어를 위에서 아래로 한 개씩 읽을 수 있도록 다시 배치한 버전이다.

표기 원칙
아래에서 “논문 직접 설명”은 저자들이 본문에서 직접 정의하거나 사용한 내용이고, “학습용 설명”은 처음 보는 사람이 이해하기 쉽게 풀어쓴 설명이다. 논문이 세부 규칙까지 정의하지 않은 부분은 일반 규칙처럼 과하게 단정하지 않는다.
기초 ①

Tree

학습용 설명: Behavior Tree에서 Tree는 여러 node가 위아래로 연결된 전체 구조를 뜻한다.

  • 맨 위에는 시작점인 Root가 있다.
  • 중간에는 판단을 담당하는 node들이 있다.
  • 맨 아래에는 최종 행동을 담당하는 leaf가 있다.
Source: Sec. IV-B에서 tree, root, leaf, node 관계 설명을 종합해 재구성
기초 ②

Node

학습용 설명: Tree를 구성하는 하나의 블록이다. 어떤 node는 판단을 담당하고, 어떤 node는 실제 action을 담당한다.

이 논문은 BT를 Root, Composite, Task, Decorator, Service 같은 여러 종류의 node로 나누어 설명한다.

Source: Sec. IV-B, journal p.32
기초 ③

Root Node

논문 직접 설명: Tree의 시작을 나타내는 node다. 모든 tree는 root node를 가지며, 각 loop는 root에서 시작해 leaf 방향으로 tree를 traverse한다.

학습용 설명: “BT 판단의 출발점”이라고 기억하면 된다.

Source: Sec. IV-B, journal p.32
기초 ④

Parent Node

학습용 설명: 어떤 node 바로 아래에 다른 node들을 거느리고 있는, 바로 위쪽의 node를 parent라고 부른다.

논문은 Selector 설명에서 “parent node”라는 표현을 사용한다.

Source: Sec. IV-B, journal p.32
기초 ⑤

Child Node

학습용 설명: 어떤 node 바로 아래에 연결된 하위 node를 child라고 생각하면 된다.

논문은 Selector 설명에서 “child nodes”라는 표현을 직접 사용한다.

Source: Sec. IV-B, journal p.32
기초 ⑥

Subnode

학습용 설명: 해당 node 아래에서 평가되는 하위 node를 가리키는 표현으로 이해하면 된다. 예를 들어 Sequence 아래 A, B, C가 연결되어 있다면 A, B, C가 그 Sequence의 subnodes다.

논문은 Sequence를 설명할 때 “multiple subnodes”와 “execution result of all subnodes”라는 표현을 쓴다.

Source: Sec. IV-B, journal p.32
기초 ⑦

Leaf Node

아래에 Child Node가 없는 마지막 Node를 Leaf Node라고 이해하면 된다.

판단 기준은 하나만 보면 된다.

“이 Node 아래에 Child가 있는가?”

없다 → Leaf Node

논문 직접 설명: 이 논문에서는 Task Node가 BT의 leaf node라고 직접 설명한다.

Source: Sec. IV-B, journal p.32
기초 ⑧

Nonleaf Node

아래에 Child Node가 하나 이상 있는 Node를 Nonleaf Node라고 이해하면 된다.

판단 기준은 역시 하나다.

“이 Node 아래에 Child가 있는가?”

있다 → Nonleaf Node

예를 들어: Selector 아래에 Task가 연결되어 있다면, Selector는 Child를 가지고 있으므로 Nonleaf이고, Task는 더 아래 Child가 없으므로 Leaf다.

논문 직접 사용: 저자들은 더 복잡한 decision-making이 필요할 경우 nonleaf nodes를 추가할 수 있다고 설명한다.

Source: Abstract; Sec. IV-A–B, journal pp.28, 32
기초 ⑨

Nonleaf와 Leaf에서 무엇을 하는가? — Decision / Execute

Leaf / Nonleaf를 구분한 다음 바로 알아야 할 내용:
논문은 BT의 동작을 아주 간단하게 “nonleaf node에서 decision을 하고, leaf node에 도달하면 그 decision을 execute한다”고 설명한다.

쉽게 풀면:

Nonleaf Node → “지금 어떤 판단/경로로 갈 것인가?”를 결정하는 쪽
Leaf Node → 판단 끝에 도달해서 실제 action을 수행하는 쪽

이 논문에서는 특히:
Task Node가 leaf node라고 직접 정의되어 있고, Task Node는 실제 action을 수행한다. 또한 이 논문의 leaf task들은 항공기가 진행해야 하는 방향인 pursuit point를 지정한다.

여기서 Execute란?
“판단 결과를 실제 행동으로 옮긴다”는 뜻으로 이해하면 된다.

즉, BT 위쪽에서 무엇을 할지 결정하고, leaf의 Task에 도달하면 그 행동을 실행한다.

주의: 논문은 모든 종류의 nonleaf node가 동일한 방식으로 decision을 수행한다고 세부적으로 분해해서 설명하지는 않는다. 여기서는 저자들이 제시한 전체적인 BT 동작 설명을 그대로 따라 이해한다.

Source: Sec. IV-A–B, journal p.32
기초 ⑩

Branch

먼저: Branch는 Tree가 갈라졌을 때 생기는 하나의 “가지/경로”라고 이해하면 된다.

Node와 Branch를 구분해서 보기

Node = 하나의 블록 / 지점
Branch = 그 지점에서 아래쪽으로 이어지는 하나의 갈래 / 경로

예를 들어:
Root 아래에서 OBFM, HABFM, DBFM으로 나뉜다면, 각각의 아래쪽 경로를 하나의 branch라고 생각하면 된다.

논문에서 직접 말하는 부분: 저자들은 Composite Node가 “어떤 branch가 실행될 것인지에 대한 기본 규칙”을 정의한다고 설명한다.

주의: 논문은 “branch”라는 용어 자체를 별도로 정의하지는 않는다. 따라서 여기서 “가지/경로”라고 설명한 부분은 Fig. 3, Fig. 7의 구조와 Composite Node 설명을 이해하기 쉽게 풀어쓴 학습용 해석이다.

Source: Sec. IV-B, journal p.32; Fig. 3, Fig. 7
기초 ⑪

한 번의 BT 판단 흐름 — Tick → 실행 → 결과 → Return → 반복

기초 ⑪~⑬은 따로 외우기보다 하나의 흐름으로 보는 편이 쉽다.
핵심은 “BT가 한 번 판단하고, 결과를 위로 전달한 뒤, 다음 tick에서 다시 판단한다”는 것이다.

먼저 이 흐름 하나만 기억하기

① Tick이 발생한다.
② Root에서 시작해 현재 상황을 판단한다.
③ 아래쪽 node를 따라 내려가 leaf/task까지 실행한다.
④ 실행/평가 결과를 True / False와 같은 결과로 표현한다.
⑤ 그 결과를 위의 parent 쪽으로 전달하는 것을 Return이라고 이해한다.
⑥ 다음 Tick이 오면 다시 현재 상황을 기준으로 판단한다.

True / False는?
“현재 평가한 node 또는 조건의 결과가 성립했는가?”를 나타내는 결과값으로 이해하면 된다. 논문은 특히 Sequence와 Selector 설명에서 true를 반환하는 조건을 직접 설명한다.

Return은?
아래쪽 child/node에서 나온 결과를 위쪽 parent node에 전달하는 것으로 이해하면 된다. 논문은 Selector가 child 중 하나가 true가 되는 순간 parent node에 true를 반환한다고 설명한다.

Tick / Loop는?
한 번 판단하고 끝나는 것이 아니라, WVR 공중전처럼 상황이 계속 변하므로 다음 tick에서 다시 tree를 평가하는 반복 구조라고 이해하면 된다.

원문 범위 주의: 논문은 Sequence/Selector가 true를 반환하는 조건과 tick 기반 반복 판단을 설명하지만, 모든 node에 대한 True/False 상태 규칙을 별도 표처럼 완전하게 정의하지는 않는다. 아래 그림은 논문 내용을 연결해서 이해하기 쉽게 만든 학습용 흐름도다.

Source: Sec. IV-B, journal p.32
한 줄로 보면:
Tick → Root → 판단 → Leaf/Task 실행 → 결과(True/False) → Parent로 Return → 다음 Tick
기초 ⑫

Tree Traversal

논문 직접 사용: 저자들은 각 loop에서 tree가 root에서 leaf 방향으로 traverse된다고 표현한다.

학습용 설명: “어떤 branch와 node를 실행할지 tree를 따라 내려가며 확인한다” 정도로 이해하면 된다.

Source: Sec. IV-B, journal p.32

이제 Selector를 보면

Selector는 갑자기 등장하는 별개의 물건이 아니라 하나의 Node다. 그리고 아래에 child를 두기 때문에 nonleaf node이며, 여러 child 가운데 결과가 성립하는 branch를 다루는 Composite Node의 한 종류다.

따라서 공부 순서는 Tree → Node → Root → Parent/Child → Subnode → Leaf/Nonleaf → Decision/Execute → Branch → Tick/결과/Return → Traversal 를 먼저 이해한 뒤, Composite → Sequence / Selector로 들어가는 것이 자연스럽다.

3. Behavior Tree의 구성요소

기초 용어를 익힌 뒤에는 Node들을 하나씩 따로 외우기보다, “시작 → 판단/분기 → 실제 행동 → 정보 보조”의 흐름으로 보는 편이 훨씬 쉽다. 이 논문 Sec. IV-B의 정의를 유지하면서, 학습용으로 아래처럼 묶어서 본다.

학습용 묶음과 논문의 공식 분류는 구분해서 보기

아래에서는 이해를 위해 Sequence / Selector / Decorator를 하나의 “판단·분기 Node 묶음”으로 같이 설명한다.

다만 논문의 공식 분류상 Sequence와 Selector는 Composite Node의 하위 유형이고, Decorator는 별도의 Node Type이다.
구성요소 ①

Root Node

Root는 Behavior Tree가 판단을 시작하는 출발점이다.

논문 직접 설명: 모든 tree에는 root node가 있고, 각 loop는 root에서 시작해 leaf node 방향으로 tree를 traverse한다.

Source: Sec. IV-B, journal p.32
구성요소 ②

판단·분기 Node 묶음 — Decorator / Selector / Sequence

먼저 왜 셋을 같이 보나?
세 Node 모두 Behavior Tree 안에서 “다음에 무엇을 할지 결정하는 과정”에 관여하기 때문에 처음 공부할 때는 하나의 묶음으로 비교하는 편이 이해하기 쉽다.

세 Node의 질문만 기억하기

Decorator → “이 조건이 맞아?”
Selector → “여러 선택지 중 지금 되는 건 뭐야?”
Sequence → “이 묶음이 전부 만족됐어?”

전투 상황으로 보면:
논문 Fig. 7c에서는 실제로 Decorator ‘OBFM?’ 다음에 Selector가 배치된다고 설명한다. 즉 먼저 “지금 OBFM 상황인가?”를 확인하고, 그 다음 OBFM 안의 세부 branch를 다루는 구조로 읽을 수 있다.

Sequence는 논문에서 모든 subnode의 execution result가 true일 때 true를 반환한다고 정의된다. 다만 본문은 Sequence가 정확히 어느 전투 block에 배치되는지를 하나씩 설명하지는 않는다. 따라서 아래의 Sequence 전투 예시는 역할을 이해하기 위한 학습용 예시다.

Source: Sec. IV-B, journal p.32; Fig. 7c
한눈에 다시:
Decorator = 입장 조건 확인
Selector = 여러 branch 중 하나 선택
Sequence = 여러 subnode 결과가 모두 True인지 확인
구성요소 ③

Task Node

Task Node는 판단 끝에 실제 action을 담당하는 Node다.

논문 직접 설명: Task Node는 실제 action을 수행하며, BT의 leaf node이다.

이 논문에서는: leaf의 Task들이 항공기가 진행해야 할 방향인 pursuit point를 지정한다.

Source: Sec. IV-B, journal p.32
구성요소 ④

Service Node

Service는 판단에 필요한 정보를 계속 가져오고 저장해 주는 보조 Node다.

논문 직접 설명: Service Node는 상황 판단에 필요한 정보를 extracting and storing하며, Composite Node의 branching이 실행되는 동안 설정된 frequency로 반복 실행된다.

논문의 실제 OBFM 예: Fig. 7c에서 OBFM 조건이 만족되면 TurnCheck와 SpeedControl이라는 Service가 실행된다고 설명한다.

여기서 특히 주의:

TurnCheck / SpeedControl이라는 이름만 보고 “실제 기체의 선회·속도를 직접 제어하는 Controller”라고 이해하면 안 된다.

논문 본문에서 Service의 역할로 확실히 설명된 것은 상황 판단에 필요한 정보를 추출하고 저장하는 것이다.
실제 기체 제어는 뒤의 Guidance & Control Model에서 수행된다.

원문 범위: 논문은 TurnCheck와 SpeedControl의 이름은 제시하지만, 각각이 정확히 어떤 변수나 Blackboard 값을 읽고 쓰는지, 내부 계산식이나 실행 주기가 무엇인지는 본문에서 자세히 설명하지 않는다.

Source: Sec. IV-B–C, journal p.32; Fig. 7c
한 줄 정리:
Service → 판단에 필요한 정보 추출·저장
Task → Pursuit Point 지정
Guidance & Control → 실제 기체 제어 명령 생성

3장을 한 번에 정리

Root에서 판단이 시작되고, Decorator / Selector / Sequence가 조건과 branch를 판단하며, 최종적으로 Task가 실제 action을 수행한다. Service는 그 판단에 필요한 정보를 준비한다.

중요: BT가 throttle, aileron, elevator, rudder를 직접 계산하는 구조로 설명되지는 않는다. 의사결정으로부터 pursuit point command가 생성되고, 그 뒤 guidance/control model이 실제 제어 명령을 만든다.

5. 실제 상위 BT 구조: OBFM / HABFM / DBFM

이 부분은 Fig. 3의 전투 상황 분류가 Fig. 6–7의 Behavior Tree에서 어떻게 큰 가지로 옮겨지는지를 같이 보면 가장 이해하기 쉽다. 즉, 먼저 현재 전투 상황을 분류하고, 그 결과에 따라 OBFM / HABFM / DBFM에 해당하는 BT node group으로 들어간다.

OBFM

Ownship이 우세한 상황

논문은 OBFM의 목적을 시간과 연료를 낭비하지 않고 가능한 빨리 적기를 격추하는 것이라고 설명한다. Turn circle에 진입한 뒤 control zone을 유지하고, 상대가 WEZ에 들어오면 무장을 사용한다.

Flow Diagram에서는 관련 maneuver가 주로 block 8–12로 설명된다.

Source: Sec. III-B, journal p.31
HABFM

양쪽이 Neutral인 High-Aspect 상황

HABFM은 상대와 ownship 어느 쪽도 우위를 가지지 못한 상황이다. 논문은 block 14–19에서 한쪽이 우위를 얻을 때까지 maneuver를 반복한다고 설명한다.

거리(room)와 energy를 비교해 one-circle 또는 two-circle maneuver를 선택하고, winning cue를 이용해 누가 우세를 얻었는지 판단한다.

Source: Sec. III-B, journal p.31; Fig. 4
DBFM

Adversary가 우세한 상황

DBFM의 목표는 가능한 오래 생존하면서 상대의 실수와 약점을 이용해 neutral 또는 ownship이 우세한 상황으로 전환하는 것이다.

논문은 상대에게 가능한 많은 geometric problem을 만들어야 한다고 설명하며, 관련 maneuver를 block 23–33으로 제시한다.

Source: Sec. III-B, journal p.32
원문 범위에서 특히 주의할 점

논문 본문은 Fig. 7c의 OBFM 상위 구현에 대해서는 첫 node가 Decorator OBFM?, 두 번째 node가 Selector라고 구체적으로 설명한다. 하지만 HABFM과 DBFM의 최상위 node 이름과 세부 node 배치를 본문 문장으로 동일한 수준까지 풀어주지는 않는다.

따라서 위 그림에서는 OBFM / HABFM / DBFM을 “BT의 큰 node group”으로만 표현하고, HABFM? / DBFM? 같은 구체적인 node 이름을 임의로 만들지 않았다.

6. 한 번에 정리

① 왜 BT를 쓰는가?

FSM은 상태와 전이가 복잡해지면 관리가 어려워지고, BT는 nonleaf node 추가를 통해 확장할 수 있으며, WVR 전투처럼 매 순간 상황이 바뀌는 환경에서 tick 단위 재평가가 가능하기 때문이다.

② 무엇으로 구성되는가?

Root, Composite (Sequence / Selector), Task, Decorator, Service 의 5종 node로 설명된다.

③ 이 논문에서는 어떻게 구성되는가?

BEM에서 공중전 maneuver 지식을 추출하여 flow diagram으로 만들고, 이를 BT의 조건/선택/행동 구조로 구현한다. BT의 상위 구조는 OBFM, HABFM, DBFM 상황을 다루며, leaf task가 pursuit point를 지정하고 이후 guidance/control model이 실제 기체 제어로 연결한다.
