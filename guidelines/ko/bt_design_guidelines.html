행동트리(BT) 설계 지침

본 지침은 행동트리의 진입조건, 노드별 책임 및 명령권 관리에 관한 설계 기준을 규정한다.

01

부모·자식 조건

상위 진입조건이 하위 기동의 진입 가능성을
모두 포함하는지 확인하여야 한다.

1-1하위 기동이 필요한 상황에서 상위 조건도 충족되는지 확인하여야 한다.

예시 상황실제 피격은 없으나 상대의 사격 위험이 감지되어 선제 회피가 필요한 경우.

틀린 예 · 상위 조건에 의한 진입 차단

사격 위험 있음 · 실제 피격 없음
상위 방어 조건: 실제 피격 여부조건 불충족 → 분기 차단
하위 선제 회피 조건: 사격 위험 여부평가되지 않음

하위 회피가 필요한 상황이 상위 진입조건에 포함되지 않는다.

바른 예 · 하위 진입 가능성 포함

사격 위험 있음 · 실제 피격 없음
상위 방어 조건: 사격 위험 또는 실제 피격조건 충족 → 분기 진입
하위 선제 회피 선택회피 명령 생성

선제 회피가 필요한 상황에서도 상위 방어 분기에 진입한다.

그림 1-1. 하위 진입 가능성 포함

1-2상위 노드와 하위 노드가 동일 상황을 서로 다른 기준으로 판단하지 않도록 공통 판단 결과를 사용하여야 한다.

예시 상황상위·하위 노드가 동일한 사격 위험을 판단하는 경우.

틀린 예 · 판단 기준의 개별 정의

동일한 상대 사격 상황
상위: 현재 조준 여부만 판단아직 정조준이 아니므로 진입 거부
하위: 예상 사격 위험도 판단회피 필요로 판단하나 도달 불가

같은 위험을 서로 다른 기준으로 판단하여 결과가 불일치한다.

바른 예 · 공통 판단 결과 사용

공통 사격 위험 판단현재 및 예상 위협을 하나의 기준으로 평가
상위 노드: 공통 결과 사용방어 분기 진입
하위 노드: 동일 결과 사용회피 기동 선택

상위·하위 노드는 동일한 위험 판단 결과를 참조한다.

그림 1-2. 공통 판단 결과 사용

02

선택 공백 방지

판단과 제어명령의 공백이
발생하지 않도록 하여야 한다.

2-1각 상황에서 판단 모듈과 기동 모듈이 적어도 하나는 선택되는지 확인하여야 한다.

예시 상황자기 기체와 상대 기체 중 어느 쪽의 일방 우세도 확정되지 않은 경우.

틀린 예 · 상황 분류 누락

일방 우세가 없는 상황
공격 우세 아님 · 방어 열세 아님해당 상황의 분기 누락
선택된 기동 없음제어명령 공백

판단 분기가 상황 전체를 포함하지 못하면 기동 선택이 중단된다.

바른 예 · 상황별 선택 경로 확보

일방 우세가 없는 상황
HABFM 분류해당 모드의 기동 조건 평가
HABFM 기동 1개 선택제어명령 생성

상황 분류부터 기동 선택까지 도달 경로를 확보한다.

그림 2-1. 상황별 선택 경로 확보

2-2개발 시 예외처리로 문제를 우회하여서는 안 된다. 예외 발생 원인은 실제 적용 전에 디버깅을 통하여 제거하여야 한다.

예시 상황방향 오차를 정규화하는 계산에 크기가 0인 오차벡터가 입력된 경우.

틀린 예 · 예외 발생 원인 미제거

방향 오차벡터 = 0이미 목표 방향에 정렬된 상태
오차벡터를 크기로 나눔0으로 나누는 연산 발생
예외처리 후 실행만 계속원인 및 명령 생성 문제 잔존

예외처리로 실행을 계속해도 잘못된 계산식은 수정되지 않는다.

바른 예 · 적용 전 원인 제거

개발 중 오차 0 입력으로 재현
정렬 상태의 계산 경로 정의정규화 없이 방향 오차 회전 보정 = 0
유효한 제어명령 생성 확인원인 제거 후 실제 적용

오차 0의 물리적 의미를 반영하여 정의되지 않는 연산을 제거한다.

그림 2-2. 적용 전 원인 제거

03

책임 분리

Service·Condition·Task의 책임을
분리하여 준수하여야 한다.

3-1Service는 관측, Condition은 판단, Task는 명령 생성을 담당하여야 한다.

예시 상황상승 기동의 관측·판단·명령 생성 기능을 노드에 배치하는 경우.

틀린 예 · 노드별 책임 혼재

Service관측과 상승 명령을 함께 생성
Condition기동 불필요로 판단
Task 미선택Service가 생성한 명령만 잔존

관측 노드가 명령을 생성하면 기동 선택과 명령 발행이 분리된다.

바른 예 · 노드별 책임 분리

Service속도·거리 등 관측값 갱신
Condition기동 필요 여부 판단
Task선택된 기동의 명령 생성

관측, 판단 및 명령 생성을 각 노드의 책임으로 구분한다.

그림 3-1. 노드별 책임 분리

3-2관측값은 한 번 계산하여 공유하여야 한다.

예시 상황하나의 제어 주기에서 여러 노드가 상대와의 거리를 사용하는 경우.

틀린 예 · 관측값 중복 계산

노드 A: 거리 계산현재 표본 사용
노드 B: 거리 재계산별도 갱신된 표본 사용
동일 주기의 판단값 불일치기동 선택과 명령 생성 기준이 달라짐

별도 계산과 표본 갱신으로 같은 관측량의 값이 달라질 수 있다.

바른 예 · 공통 관측값 공유

Service: 현재 표본 확보
거리 1회 계산 및 저장해당 제어 주기의 공통 관측값
각 노드가 동일 값 참조동일 표본·동일 계산 결과 사용

각 노드는 해당 제어 주기에 계산된 공통 관측값을 사용한다.

그림 3-2. 공통 관측값 공유

3-3Condition과 Task는 동일한 진입 판단 결과를 사용하여야 한다.

예시 상황Condition이 High-Yo-Yo 진입을 승인하여 Task에 전달하는 경우.

틀린 예 · 승인 결과와 실행 기준 불일치

Condition: 현재 판단으로 승인
Task: 이전 주기의 판단값 사용승인 결과를 전달받지 않음
선택된 상승 기동을 실행하지 않음판단과 실행 불일치

Condition의 승인과 Task의 실행이 서로 다른 판단 결과에 의존한다.

바른 예 · 승인 결과의 일관된 전달

Condition: 현재 판단으로 승인
승인 결과를 Task에 전달동일 제어 주기의 결과
Task: 승인된 기동 실행상승 명령 생성

Task는 자신을 선택한 Condition의 판단 결과를 사용한다.

그림 3-3. 승인 결과의 일관된 전달

3-4Task 내부에 별도의 진입조건을 추가하여서는 안 된다.

예시 상황트리에 표시된 진입조건을 모두 충족하였으나 Task 내부에 별도 조건이 있는 경우.

틀린 예 · Task 내부의 추가 진입조건

Condition: 기동 진입 승인
Task 내부: 별도 거리조건 검사트리에 표시되지 않은 추가 조건
추가 조건 불충족으로 실행 거부승인된 기동의 실행 차단

Task 내부의 추가 조건으로 실제 진입 기준을 파악하기 어렵다.

바른 예 · 진입조건의 명시적 배치

필요한 진입조건을 Condition에 배치별도 조건의 필요성도 이 위치에서 검토
Condition: 모든 진입조건 평가
승인 시 Task 실행추가 진입 판단 없이 명령 생성

진입 판단은 Condition에서 완료하고 Task는 승인 결과를 실행한다.

그림 3-4. 진입조건의 명시적 배치

3-5진단 노드에 명령권을 부여하여서는 안 된다.

예시 상황진단 노드가 전술 명령의 상태를 기록하는 과정에서 진단 자료 누락을 발견한 경우.

틀린 예 · 진단 기능의 명령 변경

전술 Task: 추적 명령 생성
진단 노드: 기록 자료 일부 누락진단 문제를 명령 변경 사유로 사용
진단 노드가 상승 명령으로 교체선택되지 않은 기능이 명령권 행사

진단 기능이 명령을 교체하면 전술 선택과 무관한 기동이 발생한다.

바른 예 · 진단 기능의 기록 전담

전술 Task: 추적 명령 생성
진단 노드: 누락 상태 기록명령값 변경 없음
추적 명령 전달선택된 Task의 명령권 유지

진단 노드는 관측·기록만 수행하며 명령을 생성하거나 변경하지 않는다.

그림 3-5. 진단 기능의 기록 전담

04

단일 명령권

최종 명령권을 갖는 모듈은
정확히 하나로 한정하여야 한다.

4-1진입조건이 유사한 모듈의 중복 생성 여부를 검토하여야 한다.

예시 상황동일한 사격 위험에 반응하는 회피 모듈 두 개가 등록된 경우.

틀린 예 · 중복 선택 및 명령 발행

동일한 사격 위험 감지
회피 A·회피 B가 각각 선택유사 조건을 독립적으로 적용
A 명령과 B 명령 동시 발행최종 명령권 중복

역할 구분 없이 유사 모듈을 추가하면 명령권이 중복될 수 있다.

바른 예 · 중복 검토 후 단일 선택

두 회피 모듈의 역할·조건 비교기능 중복 여부 확인
중복 기능 통합 또는 선택 우선순위 명시
회피 모듈 1개만 선택·발행최종 명령권 단일화

유사 모듈의 중복을 정리하고 최종 발행 모듈을 하나로 한정한다.

그림 4-1. 중복 검토 후 단일 선택

4-2선택 모듈 변경 시 이전 모듈의 명령권 반환 여부를 확인하여야 한다.

예시 상황High-Yo-Yo가 종료되어 정밀추적으로 전환하는 경우.

틀린 예 · 종료 모듈의 명령권 잔류

High-Yo-Yo 종료 판단
정밀추적 모듈 선택이전 상승 명령의 발행 상태 미정리
상승 명령과 추적 명령 중복이전 모듈의 명령권 잔류

후속 모듈을 선택하더라도 이전 모듈의 명령권이 남을 수 있다.

바른 예 · 명령권 반환 및 인계

High-Yo-Yo 종료 판단
이전 모듈의 명령권 반환해당 모듈의 명령 발행 종료
정밀추적 모듈로 인계해당 주기에 추적 명령 1개 발행

이전 명령권 반환과 후속 명령 생성을 연결하여 중복과 공백을 방지한다.

그림 4-2. 명령권 반환 및 인계

4-3안전 모듈은 안전한 상태로 복구되면 명령권을 반환하여야 한다.

예시 상황지면충돌 회피 후 안전 모듈의 복구 완료 조건을 충족한 경우.

틀린 예 · 복구 완료 후 선점 지속

안전 복구 완료
안전 모듈의 활성 상태 유지명령권 반환 누락
상승 명령 지속전술 기동 복귀 차단

위험이 해소되어도 안전 모듈이 명령권을 유지하면 복귀가 차단된다.

바른 예 · 복구 완료 후 명령권 반환

안전 복구 완료 확인
안전 모듈 종료 및 명령권 반환
현재 상황의 전술 모듈 선택전술 기동 재개

안전 복구 완료 시 명령권을 반환하고 현재 상황에 따라 전술을 재선택한다.

그림 4-3. 복구 완료 후 명령권 반환

05

매 주기 재평가

매 제어 주기 상위 노드부터 재평가하는
Reactive BT 구조를 적용하여야 한다.

5-1기동 종료까지의 성공 보장을 진입 시점의 필수조건으로 요구하여서는 안 된다.

예시 상황현재 회피가 필요하나 상대의 향후 기동을 확정할 수 없는 경우.

틀린 예 · 종료 성공의 사전 보장 요구

현재 회피 필요
종료까지 성공 보장 여부 검사미래 상대 기동 불확실 → 거부
필요한 회피 기동 미실행진입 차단

미래의 성공 보장을 요구하면 현재 필요한 기동이 선택되지 못한다.

바른 예 · 현재 판단 및 주기적 재평가

현재 관측에 따라 회피 선택
명령 실행 후 다음 제어 주기 진입
상위 노드부터 재평가현재 상황에 따라 지속·전환·종료

현재 필요한 기동을 실행하고 갱신된 관측으로 다음 동작을 결정한다.

그림 5-1. 현재 판단 및 주기적 재평가
